About STRIDE Threat Model Analyzer

A beginner-friendly educational tool for learning threat modelling.

What is STRIDE?

STRIDE is a threat modelling framework originally developed by Microsoft in 1999. It provides a structured way to identify and categorise security threats during the design phase of a system — before any code is written or deployed.

Each letter in STRIDE represents a category of threat:

  • Spoofing — impersonating another entity
  • Tampering — unauthorised data modification
  • Repudiation — denying an action occurred
  • Information Disclosure — exposing confidential data
  • Denial of Service — making a system unavailable
  • Elevation of Privilege — gaining unauthorised permissions

How This Tool Works

This application uses a rule-based STRIDE engine. It matches component types (user, web application, database, external API) and data flow patterns against a knowledge base of known threat patterns.

For each matching rule, the engine generates a threat entry with:

  • A description of the attack scenario
  • Likelihood and impact ratings (Low / Medium / High)
  • A risk level computed from a 3×3 risk matrix
  • Recommended mitigations and security controls

This tool does not use AI, does not connect to the internet, and does not scan any real systems. All analysis is transparent and rule-based.

Risk Matrix

Risk level is calculated from Likelihood × Impact:

Technology Stack

  • Backend: Python 3 + Flask
  • Frontend: HTML5, CSS3, Vanilla JavaScript
  • Data Storage: JSON files + Python in-memory structures
  • Diagram: HTML5 Canvas (no external libraries)
  • No paid APIs, no databases, no ML models required

Reference Standards

  • OWASP Top 10 Web Application Security Risks
  • OWASP Threat Dragon (threat modelling concepts)
  • Microsoft STRIDE Methodology
  • NIST SP 800-30 Risk Management Guide

Limitations

  • Analysis is rule-based, not exhaustive — manual review is always required.
  • The tool does not perform automated scanning or penetration testing.
  • Sample threats are based on common patterns; specific architectures may introduce unique risks.
  • Not a replacement for a professional security assessment.
